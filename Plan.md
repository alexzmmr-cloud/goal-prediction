# Plan.md: MVP «Предсказание гола» — live-алерты по ударам в створ

## 1. Текущий статус

- Приоритет: `P0`
- Текущее состояние: `план готов, разработка не начата`
- Основная цель цикла: рабочий процесс на Node.js, который по расписанию проверяет отобранные матчи Forebet, при срабатывании правила (низкий счёт + удары в створ выше порога) шлёт алерт в Telegram и пишет запись в журнал алертов с последующей возможностью проставить фактический исход.
- Обязательное ограничение: личный некоммерческий инструмент, без публикации в Google Play/App Store, без автоматической постановки ставок — только уведомление, решение о ставке принимает пользователь вручную. Один процесс (не микросервисы), запускается локально на ноутбуке на этом цикле, но пишется без хардкода под конкретную машину, чтобы позже перенести на сервер/облако без переписывания.
- Основной контекст проекта: описание идеи, критический разбор и вся логика триггеров зафиксированы в переписке текущего цикла (нет отдельного README.md/spec.md на момент начала цикла — детали ниже воспроизведены полностью, отдельно сверяться не с чем).
- Секреты: токен Telegram-бота (`TELEGRAM_BOT_TOKEN`) и chat ID (`TELEGRAM_CHAT_ID`) — хранить в `.env`, не коммитить, не печатать в логах и не вставлять в ответы ИИ.
- Сейчас в работе: `не начато — следующий шаг 1`.

## 1.1 Целевой сценарий

Пользователь (единственная роль в проекте) должен пройти один основной маршрут:

1. Запускает процесс на ноутбуке (`node index.mjs` или аналог) один раз в начале дня/сессии наблюдения.
2. Процесс сам получает дневной список матчей с Forebet, фильтрует по прематч-прогнозному тоталу ≥3.
3. Для каждого отобранного матча процесс по расписанию проверяет статистику на контрольных точках: 15′ и 25′ (1-й тайм), затем 50′/60′/70′/80′ (2-й тайм).
4. Правило разное по таймам (уточнено пользователем по факту наблюдения за реальными матчами): в 1-м тайме (15′/25′) — счёт строго 0:0 и удары в створ с начала матча > 2 у любой команды; во 2-м тайме (50′/60′/70′/80′) — счёт «низкий» (0-0, 0-1, 1-1, 1-0) и удары в створ > 4 у любой команды (порог выше, чем в 1-м тайме — иначе 2-3 удара за 50-80 минут игры не редкость и не показатель скорого гола). При выполнении правила — пользователь получает сообщение в Telegram с названием матча, счётом, минутой и текущей статистикой ударов.
5. Пользователь читает алерт в Telegram на телефоне, вручную открывает live-трансляцию/статистику и сам принимает решение по ставке — приложение решение не принимает.
6. После завершения матча (или по ходу) пользователь может проставить фактический исход сработавшего алерта (был гол после сигнала или нет) — это пишется в журнал для последующей ручной калибровки порога.

## 1.2 Что не входит в текущую версию

- Публикация в Google Play/App Store, нативное Android-приложение.
- Автоматическая постановка ставок или интеграция с букмекерскими API.
- Мультиканальные алерты (email, push, Discord) — только Telegram.
- Мониторинг матчей вне отобранных по прематч-фильтру тотал≥3.
- Непрерывный live-polling (обновление раз в секунды/минуту) — только фиксированные контрольные точки.
- Адаптивный/самообучающийся порог по ударам в створ — порог фиксированный, калибровка вручную по журналу.
- Учёт «опасных атак» и общих ударов по воротам как отдельных критериев срабатывания — используются только удары в створ (опасные атаки и удары по воротам — вне MVP, зафиксировано как допущение ниже).
- UI/дашборд — управление только через запуск процесса и чтение Telegram-сообщений.
- Деплой на сервер/облако — в этом цикле процесс запускается локально, перенос на сервер зафиксирован как совместимость на будущее, но не делается.
- Анализ/хранение данных по завершённым или вышедшим за диапазон «низких» матчам — как только матч перестаёт быть интересен (счёт вырос, стал `out_of_range`, или матч закончился), проект не тратит на него ресурсы; ценность представляет только сам факт сработавшего сигнала (фиксируется журналом алертов), не архив статистики по всему матчу.

## 1.3 Допущения и открытые вопросы

### Допущения

- Источник данных — Forebet (и для прематч-прогноза, и для live-статистики по ходу матча), скрейпинг через headless-браузер по образцу `sites/forebet.mjs` из проекта FOOTBALL-TIPS.
- «Низкий счёт» разный по таймам (уточнено пользователем по факту наблюдения за реальными матчами): в 1-м тайме (15′/25′) — строго 0:0; во 2-м тайме (50′/60′/70′/80′) — фиксированный список 0-0, 0-1, 1-1, 1-0 (разница ≤1 гол, суммарный тотал на тот момент ≤2).
- Условие по ударам в створ — ИЛИ (срабатывает по любой из двух команд, не обязательно по обеим одновременно).
- Порог по ударам в створ разный по таймам: 1-й тайм (15′/25′) — `>2`, 2-й тайм (50′/60′/70′/80′) — `>4` (выше, потому что за 50-80 минут игры 2-3 удара в створ у команды — не редкость и не показатель скорого гола, а просто шум). Оба порога — кумулятивный счёт ударов с начала матча (0′), не за отдельный тайм.
- Отсечки 15′ и 25′ применяются только если к этому моменту ещё идёт 1-й тайм и счёт 0:0 (иное — вне зоны внимания на этих отсечках); 15′ и 25′ независимы друг от друга — нет логики «рост между точками», каждая проверяется отдельно тем же правилом.
- Если гол забит в 1-м тайме (счёт вышел из 0:0 до 25′ или между 25′ и перерывом), отсечки 2-го тайма всё равно проверяются по счёту на тот момент (список 0-0/0-1/1-1/1-0 применяется к текущему счёту на каждой отсечке независимо, не блокируется историей 1-го тайма) — счёт вне {0-0} на отсечках 1-го тайма НЕ переводит матч в `out_of_range` (это состояние применяется только к отсечкам 2-го тайма).
- Алерт по матчу считается разовым на контрольную точку: если условие истинно на нескольких отсечках подряд (например, 50′ и 60′) без изменения счёта — уведомление в Telegram отправляется на каждой такой отсечке отдельно (не подавляется повтор), пользователь сам оценивает актуальность повторного сигнала.
- Мониторинг конкретного матча прекращается, когда либо пройдены все применимые отсечки (15′/25′ или 50/60/70/80′ по обстоятельствам), либо счёт на отсечке 2-го тайма вышел за пределы списка «низких» (тогда дальнейшие отсечки для этого матча пропускаются — окончательно, без возврата к мониторингу, даже если счёт позже снова попадёт в диапазон «низких», например 1-0 → 2-0 → 2-1).
- Ориентир для наступления отсечки — игровая минута, которую показывает сам Forebet на странице матч-центра (а не расчётное время «кик-офф + N минут»), поскольку реальные матчи стартуют с задержкой и содержат остановки/добавленное время, которые расчётное время не учитывает.
- Процесс на этом цикле работает без retry/recovery: если ноутбук выключен/процесс не запущен в момент наступления отсечки — эта отсечка для матча просто пропускается, без досрочной/отложенной проверки постфактум. Восстановление пропущенных отсечек — вне скоупа MVP.
- Frontend/UI не создаётся — весь интерфейс с пользователем это Telegram-чат с ботом.

## 2. Требования к результату

- Скрипт получает дневной список матчей Forebet и фильтрует по прематч-тоталу ≥3 без участия пользователя.
- Для каждого отобранного матча скрипт хранит своё состояние (какие отсечки уже пройдены, сработал ли алерт, финальный счёт по последней проверке).
- Проверка на контрольных точках (15′, 50′, 60′, 70′, 80′) выполняется скриптом по расписанию — не вручную пользователем.
- Правило алерта реализовано ровно так, как зафиксировано в разделе 1.3 (счёт из списка + удары в створ >2 у любой команды, кумулятивно).
- При срабатывании правила — сообщение в Telegram с минимальным набором данных: название матча, счёт, минута, текущие удары в створ по обеим командам.
- Каждое сработавшее уведомление сохраняется в журнал алертов (файл) с возможностью позже вручную дописать фактический исход.
- Секреты (токен бота, chat id) читаются из `.env`, нигде не хардкожены в коде.
- Код не завязан на абсолютные пути/особенности конкретного ноутбука — совместим с последующим переносом на сервер без переписывания логики.
- Не добавлять сверх плана: мультиматчевый дашборд, автоматическую калибровку порога, поддержку других источников кроме Forebet.

## 2.1 Раскладка по слоям

### Frontend

- Не затрагивается на этом цикле — интерфейса нет, взаимодействие только через Telegram-чат с ботом.

### Backend

- Модуль скрейпинга дневного списка матчей Forebet + фильтр по тоталу ≥3 (расширение подхода `sites/forebet.mjs` из FOOTBALL-TIPS).
- Модуль скрейпинга live-статистики конкретного матча (счёт, удары в створ по обеим командам) со страницы матч-центра Forebet.
- Планировщик контрольных точек по каждому отслеживаемому матчу (15′, 50′, 60′, 70′, 80′ от фактического времени старта матча).
- Модуль применения правила алерта (сравнение счёта со списком «низких» + сравнение суммарных ударов в створ с порогом).
- Telegram-бот (`telegraf` либо `node-telegram-bot-api`) — отправка сообщения при срабатывании правила.
- Журнал алертов — запись сработавших случаев с возможностью ручного дополнения исхода.

### Database

- Формат хранения — JSON-файлы в `data/` (по образцу FOOTBALL-TIPS), если на шаге 5 не будет принято иное решение.
- `MatchWatch` (состояние наблюдения за матчем): id матча (или связка команд+дата), команда-хозяин, команда-гость, прогнозный тотал, время кик-оффа, список пройденных отсечек, список пропущенных отсечек (`skippedCheckpoints` — отметки, которые нельзя было честно проверить из-за таймингов, например 15′ при позднем старте наблюдения уже во 2-м тайме; семантически отдельно от будущих ошибок доступности Forebet на шаге 4), статус (`наблюдается` / `завершено` / `гол-вышел-из-диапазона`).
- `Alert` (запись сработавшего алерта): id матча, минута отсечки, счёт на момент отсечки, удары в створ хозяева/гости, время отправки в Telegram, поле исхода (`не проставлен` / `гол-после-сигнала` / `гол-не-случился`) — заполняется вручную пользователем.
- Статусы `MatchWatch.status`: `watching`, `done`, `out_of_range`.
- Статусы `Alert.outcome`: `pending`, `goal_followed`, `no_goal`.
- Связь: `MatchWatch` → `Alert[]` (один матч может дать несколько алертов на разных отсечках).
- Ключевое правило: удары в створ в `Alert` фиксируются как суммарные с начала матча на момент конкретной отсечки (снапшот, не дельта между отсечками).
