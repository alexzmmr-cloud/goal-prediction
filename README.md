# Goal Prediction

Личный некоммерческий live-трекер футбольных матчей: отбирает по прематч-прогнозу
Forebet матчи с высоким ожидаемым тоталом голов, отслеживает их в определённые
контрольные точки по ходу игры и присылает алерт в Telegram, когда счёт ещё
низкий, а удары в створ у одной из команд превышают порог. Решение о ставке
пользователь принимает сам — приложение только сигнализирует.

## Основные возможности

* Дневной отбор матчей Forebet по прогнозному тоталу ≥3.
* Мониторинг отобранных матчей на фиксированных контрольных точках (1-й тайм:
  15′, 25′; 2-й тайм: 50′, 60′, 70′, 80′) вместо непрерывного polling.
* Правило алерта разное для каждого тайма: в 1-м тайме — счёт строго 0:0 и
  удары в створ > 2 у любой из команд; во 2-м тайме — счёт из списка «низких»
  (0-0, 0-1, 1-1, 1-0) и удары в створ > 4 у любой из команд (порог выше,
  чем в 1-м тайме, — иначе 2-3 удара за 50-80 минут игры не редкость и не
  показатель скорого гола).
* Уведомление о сработавшем алерте в Telegram.
* Журнал всех сработавших алертов (`data/alerts-<дата>.json`) с возможностью
  вручную проставить фактический исход (`set-outcome.mjs`) — для последующей
  ручной калибровки порога.
* Как только счёт матча выходит за пределы «низких» — матч больше не
  отслеживается.

## Стек и инструменты

* Node.js (ESM, `.mjs`)
* [Playwright](https://playwright.dev/) + [playwright-extra](https://www.npmjs.com/package/playwright-extra) с
  [puppeteer-extra-plugin-stealth](https://www.npmjs.com/package/puppeteer-extra-plugin-stealth) — обход
  Cloudflare managed challenge на Forebet
* [Telegraf](https://telegraf.js.org/) — Telegram-бот
* [dotenv](https://www.npmjs.com/package/dotenv) — переменные окружения

## Структура проекта

* `browser.mjs`, `browser-stealth.mjs` — обёртки над Playwright (обычный и
  stealth-режим запуска браузера)
* `sites/forebet-today.mjs` — скрейпинг дневного списка прогнозов Forebet и
  фильтр по прогнозному тоталу
* `sites/forebet-live.mjs` — чтение текущей минуты и live-статистики
  конкретного матча (перехват сетевого ответа `get_evs_n.php`, а не
  DOM-парсинг)
* `sites/forebet-kickoff.mjs` — грубый фильтр по времени кик-оффа: не даёт
  опрашивать матч, который заведомо ещё не мог начаться (чтобы не открывать
  браузер впустую весь день для вечерних матчей)
* `scheduler.mjs` — состояние наблюдения за матчем и опрос по контрольным
  точкам
* `alert-rule.mjs` — правило срабатывания алерта
* `alert-log.mjs` — журнал алертов (запись, чтение, простановка исхода)
* `telegram.mjs` — отправка сообщений в Telegram
* `run.mjs` — основной процесс: фильтр → мониторинг → алерт → Telegram +
  журнал
* `start.sh` — рекомендованная точка входа (`caffeinate -is node run.mjs`,
  защита от сна macOS при закрытой крышке — см. «Запуск»)
* `set-outcome.mjs` — CLI для ручной простановки исхода алерта
* `run-filter.mjs`, `find-live.mjs`, `test-live-read.mjs` — вспомогательные
  скрипты для разовой проверки фильтра/поиска live-матчей/чтения статистики
* `test-*.mjs` — юнит- и интеграционные тесты компонентов (без фреймворка,
  запускаются напрямую через `node`)
* `Plan.md` — полная история решений, допущений и хода разработки проекта
* `data/` — журналы алертов (не коммитится, см. `.gitignore`)
* `.env.example` — шаблон переменных окружения, копируется в `.env` (см. «Запуск»)

## Запуск

Установка (один раз):

```bash
npm install
npx playwright install chromium
```

Настройка секретов — скопировать `.env.example` в `.env` и заполнить:

```bash
cp .env.example .env
```

* `TELEGRAM_BOT_TOKEN` — токен бота от [@BotFather](https://t.me/BotFather) в Telegram.
* `TELEGRAM_CHAT_ID` — свой chat id (написать боту любое сообщение, затем
  запросить `https://api.telegram.org/bot<TELEGRAM_BOT_TOKEN>/getUpdates` и
  найти `chat.id` в ответе).
* `CHROMIUM_PATH` — опционально, путь к бинарнику Chromium, если путь по
  умолчанию в `browser.mjs`/`browser-stealth.mjs` не подходит для этой
  машины.

Основной запуск (мониторинг матчей дня и отправка алертов в Telegram):

```bash
./start.sh
```

Оборачивает `node run.mjs` в `caffeinate -is`, чтобы macOS не ушла в сон по
простою или закрытой крышке (актуально при работе на внешнем мониторе) и не
остановила мониторинг на середине дня. Останавливается как обычный процесс
(Ctrl+C) — обычное поведение сна возвращается автоматически, без какой-либо
ручной настройки.

Прямой запуск без защиты от сна (например для отладки на короткое время,
когда крышка точно останется открытой):

```bash
node run.mjs
```

## Полезные команды

* `node run-filter.mjs [minTotal]` — посмотреть, какие матчи дня проходят
  фильтр по прогнозному тоталу (по умолчанию 3), без полного цикла
  мониторинга.
* `node set-outcome.mjs <date:YYYY-MM-DD> <id> <goal_followed|no_goal>` —
  вручную проставить исход сработавшего алерта в журнале.
* `node test-alert-rule.mjs`, `node test-scheduler.mjs <matchUrl> <matchId>`,
  `node test-alert-log.mjs`, `node test-telegram-format.mjs`,
  `node test-out-of-range.mjs`, `node test-scheduler-late-start.mjs
  <matchUrl> <matchId>`, `node test-kickoff.mjs` — точечные проверки
  отдельных модулей.
* `node --check <файл>.mjs` — проверка синтаксиса.

## Что важно знать при работе с проектом

* Источник данных — Forebet, за Cloudflare managed challenge; скрейпинг
  нестабилен от попытки к попытке (см. retry-логику в `run.mjs` и
  `run-filter.mjs`), это ожидаемое поведение источника, а не баг.
* Live-статистика матча получается не парсингом HTML, а перехватом ответа
  внутреннего JSON-эндпоинта Forebet (`get_evs_n.php`) внутри открытой
  Playwright-страницы — подробности в `Plan.md`, шаг 1.
* Матч не опрашивается, пока по времени кик-оффа из дневного списка ещё
  заведомо рано (см. `sites/forebet-kickoff.mjs`) — иначе при запуске
  утром скрипт впустую дёргал бы вечерние матчи браузером каждую минуту.
  Это грубый фильтр только для экономии ресурсов, реальным критерием
  «матч идёт» остаётся игровая минута со страницы самого матча.
* `.env` не коммитится (см. `.gitignore`) — секреты никогда не должны
  попадать в git.
* Проект рассчитан на личное некоммерческое использование: без публикации в
  сторы, без автоматической постановки ставок — только уведомление,
  решение принимает пользователь.
* Полная история решений, допущений и открытых вопросов — в `Plan.md`.
